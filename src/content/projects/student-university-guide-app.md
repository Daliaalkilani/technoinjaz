# تطوير دليل الطالب الرقمي

مشروع أكاديمي لتطوير **تطبيق دليل الطالب الجامعي الرقمي**، نفذه فريق من الطلاب بمساعدة ودعم تقني من **مكتب تكنو إنجاز** أثناء مراحل التطوير. يجمع التطبيق في واجهة واحدة المعلومات الأكاديمية التي يحتاجها الطالب: الاختصاصات وخططها الدراسية، والمقررات حسب السنة، والكادر التدريسي، وإنجازات الجامعة، مع بحث شامل ومساعد افتراضي، بدل الاعتماد على مصادر متفرقة قد لا تكون محدّثة.

بُني تطبيق الهاتف بإطار **Flutter**، والجانب الخلفي ولوحة الإدارة على الويب بإطار **Laravel**، مع قاعدة بيانات علائقية وواجهات **RESTful API** محمية بـ **Laravel Sanctum**. ويستخدم المساعد الافتراضي **Google Gemini** لفهم نية سؤال المستخدم ومطابقته مع قائمة محددة من الأسئلة الشائعة، ثم يعرض الإجابة المعتمدة من قاعدة المعرفة المحلية، لا إجابة مولّدة بحرية.

## حقائق المشروع

| العنصر | البيانات |
|---|---|
| نوع المشروع | تطبيق هاتف لدليل أكاديمي مع لوحة إدارة ويب |
| المجال | تطبيقات الهاتف، تطوير الويب، الخدمات الجامعية الرقمية |
| السنة | 2024–2025 |
| حالة المشروع | نموذج تطبيقي أكاديمي بواجهات هاتف (Android) ولوحة إدارة |
| دور تكنو إنجاز | دعم ومساعدة تقنية للطلاب أثناء تطوير المشروع |
| تقنيات أساسية | Flutter / Dart، Laravel / PHP، Eloquent ORM، Laravel Sanctum، قاعدة بيانات علائقية، Google Gemini |
| المخرجات | تطبيق هاتف بواجهات متعددة، لوحة إدارة ويب، API لربط التطبيق بالخادم، مساعد افتراضي محدود بقاعدة أسئلة شائعة |

## المشكلة التي تناولها المشروع

انطلق المشروع من صعوبة يواجهها كثير من الطلاب، خاصة في السنوات الأولى، في الوصول إلى معلومات دقيقة وشاملة عن تخصصاتهم، والمقررات المطلوبة، والأساتذة المسؤولين عن كل مادة، ومتطلبات التخرج. فالطالب يعتمد غالبًا على مصادر شفهية أو ورقية متفرقة قد تكون غير دقيقة أو غير محدثة، ما يضعف قدرته على تخطيط مساره الدراسي.

لذلك ركز المشروع على إنشاء نقطة وصول رقمية موحدة تتيح للطالب البحث في المحتوى الأكاديمي بصورة منظمة، مع لوحة إدارة تتيح تحديث المعلومات دوريًا حتى لا يتحول التطبيق إلى محتوى جامد لا يواكب تغير المناهج والكوادر.

## دور مكتب تكنو إنجاز

نُفذ المشروع أكاديميًا بواسطة الطلاب، مع **مساعدة ودعم تقني من مكتب تكنو إنجاز أثناء مراحل التطوير**. ولا تنسب هذه الصفحة إلى المكتب ملكية المشروع أو تنفيذ جميع عناصر Flutter وLaravel وقاعدة البيانات والمساعد الافتراضي بصورة منفردة؛ دوره هو **المساندة التقنية للطلاب خلال التنفيذ**.

## مراحل العمل

اتبع المشروع منهجية مرنة من أربع مراحل:

1. تحليل المتطلبات وتحديد احتياجات المستخدمين والوظائف الأساسية.
2. تصميم قاعدة بيانات علائقية تغطي الكيانات الأساسية والعلاقات بينها مع مراعاة التوسع.
3. تصميم الواجهات وفق مبادئ UI/UX بالتركيز على البساطة وسهولة التصفح.
4. تطوير تطبيق Flutter ولوحة Laravel وربطهما عبر واجهات برمجية.

## تجربة الطالب داخل التطبيق

تشمل النسخة الموثقة الواجهات التالية:

| الواجهة | ما تعرضه |
|---|---|
| الواجهة الرئيسية | أقسام الاختصاصات الأكاديمية والكادر التدريسي ومشاريع التخرج مع بحث مباشر، ودعم للوضع الليلي |
| القائمة الجانبية | الصفحة الرئيسية، وملفي الشخصي، ومقرراتي المسجلة، والتقويم الأكاديمي، والجداول الدراسية، والإعدادات، وتسجيل الخروج |
| الملف الشخصي | الاسم والبريد الإلكتروني والرقم الجامعي والاختصاص وسنة التسجيل، مع تعديل الملف وتغيير كلمة المرور |
| البحث الشامل | نتائج من الاختصاصات والمقررات معًا عند كتابة كلمة بحث |
| الاختصاصات الأكاديمية | قائمة بالاختصاصات الهندسية المتاحة وصفحة تفاصيل لكل اختصاص |
| الخطة الدراسية | مخطط يوضح تسلسل المواد ومتطلباتها لكل اختصاص |
| المقررات | تصفح المقررات حسب السنة الدراسية من الأولى إلى الخامسة، مع عدد الوحدات لكل مقرر |
| المساعد الافتراضي | دردشة للإجابة عن الأسئلة الشائعة |
| إنجازات الجامعة | مسابقات وأنشطة مع تاريخ آخر تحديث للمعلومة |

## المساعد الافتراضي

بُني المساعد الافتراضي داخل تطبيق Flutter حول نموذج من **Google Gemini** (يذكر المشروع gemini-1.5-flash مثالًا)، ويعمل بالطريقة الآتية:

1. عند فتح الشاشة يُهيّأ النموذج وجلسة دردشة، ويرسل المساعد رسالة ترحيب تتضمن قائمة من الأسئلة التي يستطيع الإجابة عنها.
2. إذا كانت رسالة المستخدم تحية فقط، يرد التطبيق بعبارة ترحيب مباشرة.
3. غير ذلك، يُرسل السؤال إلى Gemini مع قائمة الأسئلة الشائعة كاملة ضمن تعليمات موجّهة، ويُطلب منه إرجاع السؤال المطابق تمامًا أو عبارة "غير متوفر".
4. إذا أعاد النموذج سؤالًا موجودًا في القائمة المحلية، يعرض التطبيق الإجابة المقابلة المخزنة في التطبيق، وهي مأخوذة من الموقع الرسمي للجامعة.
5. إذا لم يوجد تطابق، يعتذر المساعد ويوضح أنه مخصص للأسئلة الشائعة المحددة، ويقترح سؤالًا آخر من القائمة.

هذا الأسلوب يجعل وظيفة الذكاء الاصطناعي في المشروع محددة: **تحليل السؤال والمطابقة الدلالية مع قاعدة معرفة مضبوطة**، وليس إنشاء إجابات أكاديمية مفتوحة أو تقديم إرشاد أكاديمي شخصي غير مقيد، ما يقلل احتمال تقديم معلومات غير معتمدة.

وللاستزادة، اقرأ مقالينا [كيف تتنبأ نماذج الذكاء الاصطناعي بالكلمة التالية؟](/articles/next-token-prediction) و[ما هو بروتوكول MCP ومتى يكون التكامل المباشر أبسط؟](/articles/model-context-protocol-mcp).

## لوحة الإدارة وإدارة المحتوى

إلى جانب تطبيق الهاتف، يتضمن المشروع لوحة إدارة ويب مبنية بـ Laravel، تشمل:

| الواجهة | الوظيفة |
|---|---|
| لوحة القيادة | إحصائيات سريعة لعدد الفعاليات النشطة والمدرسين والمقررات والطلاب، وقسم لمشاريع التخرج |
| إدارة الكليات | إضافة الكليات وعرضها بالاسمين العربي والإنجليزي مع التعديل والحذف |
| إدارة الاختصاصات | إضافة الاختصاصات وعرض حالتها والكلية التابعة لها مع الفلترة |
| إدارة المقررات | إضافة المقررات وتعديلها بالاسم العربي والإنجليزي والرمز والاختصاص وعدد الساعات |
| مراجعة طلبات التسجيل | طلبات تسجيل الطلاب في الفعاليات أو المقررات مع حالتها وتاريخها والرقم الجامعي |
| إدارة مديري النظام | إضافة المديرين وتحديد أدوارهم، مثل مدير عام أو مدير محتوى |

## البنية التقنية

اعتمد المشروع على فصل تطبيق الهاتف عن الجانب الخلفي ولوحة الإدارة:

- **Flutter / Dart:** تطبيق الهاتف وواجهاته.
- **Laravel / PHP:** منطق الخادم وفق نمط MVC، مع نماذج **Eloquent** لكل جدول، ومتحكمات مقسمة بين مجلد Api (استجابات JSON للتطبيق) ومجلد Admin (واجهات Blade للوحة الإدارة).
- **المصادقة:** جلسات Laravel لمديري لوحة الإدارة عبر حارس مستقل (admin_web)، ورموز **Laravel Sanctum** لطلاب التطبيق مع حماية مسارات API بطبقة auth:sanctum.
- **التحقق والتنسيق:** فئات Form Request للتحقق من المدخلات، وAPI Resources لتوحيد بنية استجابات JSON وتقليل حجمها، مع تقسيم النتائج إلى صفحات (Pagination) والتحميل المسبق للعلاقات.
- **قاعدة بيانات علائقية:** جداول للطلاب والكليات والاختصاصات والمقررات وأعضاء الهيئة التدريسية والمشاريع والفعاليات والوسائط والتنبيهات، وجداول ربط لتسجيل الطلاب في المقررات والفعاليات، وجداول تسجل إجراءات المديرين على المحتوى.
- **Google Gemini:** تحليل نية الاستفسار ومطابقته مع الأسئلة الشائعة المحددة.

ومن الأدوات التي يستعرضها المشروع أيضًا إطار Bootstrap لتصميم واجهات الويب المتجاوبة، واستضافة Hostinger.

## ما يذكره المشروع عن النتائج

يذكر المشروع أنه قُيّمت التجربة عبر اختبارات مستخدمين داخل الجامعة، ولوحظ تحسن في سرعة وصول الطلاب إلى المعلومة **يُقدَّر بنحو 25%**، وزيادة في التفاعل مع المحتوى الجامعي **تقارب 40%** مقارنة بالطريقة التقليدية. لكنه لا يذكر عدد المشاركين في الاختبار، ولا طريقة قياس هذه النسب، لذلك تُفهم على أنها تقديرات أولية لا نتائج تقييم منهجي.

أما النسب الأخرى الواردة في مقدمة المشروع، مثل نسب استخدام الطلاب للتطبيقات الجامعية، فهي من دراسات وتقارير سابقة وليست نتائج هذا التطبيق.

## حدود النسخة الحالية

النسخة الموثقة من المشروع ليست نظام معلومات أكاديميًا رسميًا متكاملًا مع جميع الأنظمة المؤسسية. من حدودها:

- الاقتصار على بيانات تخصصات محددة توفرت من الجهات المتعاونة، دون تغطية جميع الكليات.
- دعم نظام Android فقط في النسخة الأولى، مع إرجاء iOS إلى مراحل لاحقة.
- التركيز على العرض والتصفح دون تفاعل معمق مثل تقييم المواد.
- عدم وجود تكامل مع أنظمة الدرجات والجداول الرسمية، وتحديث البيانات يدويًا من لوحة الإدارة.
- عدم تضمين أنظمة إحصائية متقدمة في لوحة الإدارة في هذه المرحلة.
- المساعد الافتراضي محدود بالأسئلة الشائعة المبرمجة، ويحتاج إلى اتصال بالإنترنت للوصول إلى Gemini.

## تطويرات مستقبلية محتملة

بحسب ما يقترحه المشروع:

- دعم منصة iOS.
- الربط مع أنظمة الجامعة الرسمية لتسجيل المواد والدرجات والجداول.
- نظام إشعارات ذكي يرسل تنبيهات حسب اهتمامات الطالب أو تغيّر المحتوى.
- تسجيل دخول موحد (SSO) عبر البريد الجامعي.
- تمكين أعضاء الهيئة التدريسية من رفع المحتوى التعليمي مباشرة.
- أدوات إحصائية وتقارير لتحليل تفاعل الطلاب مع النظام.
- مساحة للنشاطات اللاصفية والفرص التطوعية.

## مشروع طلابي مشابه؟

إذا كنت تعمل على مشروع برمجي أو نظام رقمي وتحتاج إلى دعم تقني في التخطيط أو التطوير أو المراجعة، يمكن التواصل مع **تكنو إنجاز** لمناقشة نطاق المساعدة المناسب للمشروع.

## هل تخطط لنظام مشابه؟

إذا كنت تعمل على تطبيق دليل رقمي بمساعد افتراضي وتحتاج إلى مساعدة تقنية في تطوير الفكرة أو بناء نموذج أولي، يمكن التواصل مع **مكتب تكنو إنجاز** لمناقشة متطلبات المشروع ونطاق الدعم المناسب.
