# CyberShield: تطبيق ذكي لفحص الملفات والروابط

**CyberShield** تطبيق للهواتف المحمولة يساعد المستخدم على التحقق من سلامة **الملفات والروابط الإلكترونية** قبل التعامل معها، نفذه فريق من الطلاب بمساعدة تقنية من **مكتب تكنو إنجاز**. يرسل التطبيق الرابط أو البصمة الرقمية للملف (SHA-256) إلى خدمة **VirusTotal** التي تجمع نتائج عشرات محركات مكافحة البرمجيات الخبيثة، ثم يمرر النتيجة التقنية الخام إلى **Google Gemini** ليحولها إلى تقرير أمني مبسط يوضح مستوى الخطورة وسببه ويقدم نصائح وقائية.

بُني التطبيق بإطار **Flutter** لنظام Android، مع خادم خلفي عديم الخوادم على **Cloudflare Workers** وإطار Hono، وقاعدة بيانات **Cloudflare D1** وتخزين مؤقت **Cloudflare KV**، ومصادقة بالرموز **JWT**. والنتيجة الموثقة نموذج عامل ينفذ فحص الروابط والملفات ويعرض تقريرًا مفهومًا لغير المتخصصين، مع سجل للفحوصات وإدارة للحساب، دون أن يتضمن الكتاب قياسات كمية لدقة الكشف أو زمن الاستجابة.

## حقائق المشروع

| العنصر | البيانات |
|---|---|
| نوع المشروع | تطبيق هاتف محمول للأمن السيبراني مدعوم بالذكاء الاصطناعي |
| المجال | الأمن السيبراني، فحص الروابط والملفات، الذكاء الاصطناعي التوليدي |
| حالة المشروع | نموذج عامل على Android مع خادم خلفي سحابي |
| دور تكنو إنجاز | دعم ومساعدة تقنية للطلاب أثناء تطوير المشروع |
| تقنيات أساسية | Flutter، Riverpod، GoRouter، Dio، Cloudflare Workers، Hono، Cloudflare D1، Cloudflare KV، VirusTotal API، Google Gemini API، JWT |
| المخرجات | تقرير أمني مبسط (مستوى الخطورة، ملخص، نصائح وقائية)، تفاصيل نتائج VirusTotal، سجل فحوصات، إحصائيات استخدام |

## المشكلة التي يعالجها المشروع

أصبحت الهواتف الذكية المنصة الأساسية للمعاملات اليومية، وصارت بذلك هدفًا مباشرًا لهجمات التصيد الاحتيالي والبرمجيات الخبيثة التي تصل غالبًا عبر رابط أو ملف. ويحدد المشروع ثلاث فجوات في الحلول القائمة:

- **محدودية المحرك الواحد:** كثير من التطبيقات الأمنية يعتمد على محرك كشف واحد، ما يضعف الكشف أمام التهديدات الجديدة.
- **المفاضلة بين الدقة والموارد:** الحلول الأدق، مثل نماذج التعلم العميق التي تعمل على الجهاز، تستهلك البطارية والمعالج وترفع زمن الاستجابة.
- **الفجوة المعرفية في التقارير:** التقارير الأمنية المعتادة تقنية ومعقدة، ولا يستطيع المستخدم العادي تفسيرها واتخاذ قرار بناءً عليها.

يعالج CyberShield هذه الفجوات بمعمارية هجينة: فحص متعدد المحركات عبر خدمة سحابية بدل محرك محلي واحد، وإرسال بصمة الملف بدل الملف نفسه لتقليل استهلاك البيانات، ووكيل ذكاء اصطناعي يحول النتيجة إلى لغة مفهومة.

## دور مكتب تكنو إنجاز

نُفذ المشروع أكاديميًا بواسطة الطلاب، مع **مساعدة ودعم تقني من مكتب تكنو إنجاز أثناء مراحل التطوير**. ويُعرض ضمن أعمال المكتب مثالًا على دعمه لتطبيقات الأمن السيبراني التي تدمج خدمات الفحص السحابية مع النماذج اللغوية في تطبيقات الهاتف.

## آلية عمل التطبيق

يمر طلب الفحص بمسار متسلسل من إدخال المستخدم حتى عرض التقرير:

1. يسجل المستخدم دخوله، ثم يختار فحص ملف أو فحص رابط ويضغط زر الفحص.
2. يرسل التطبيق الطلب إلى الخادم الخلفي، الذي ينشئ سجل فحص جديدًا في قاعدة البيانات بحالة **Pending** ويعيد معرف العملية، بينما يعرض التطبيق شاشة انتظار.
3. يتواصل الخادم مع **VirusTotal API**: في حالة الملف تُرسل **بصمة SHA-256** المولدة له، فإن كانت معروفة لدى الخدمة يُسترجع تقريرها مباشرة دون رفع الملف الفعلي؛ وفي حالة الرابط يُمرر الرابط نفسه للتحليل.
4. يعيد VirusTotal تقريرًا خامًا بصيغة JSON يتضمن عدد المحركات التي صنفت العنصر خبيثًا أو مشبوهًا أو غير ضار أو لم تكتشفه، فيحفظه الخادم مرتبطًا بسجل الفحص.
5. يرسل الخادم التقرير الخام إلى **Google Gemini** مع تعليمات موجهة (Prompt)، فيولد النموذج ملخصًا يتضمن مستوى الخطورة ووصفًا مختصرًا للحالة ونصائح وقائية.
6. يُحفظ التقرير المبسط وتُحدَّث حالة الفحص إلى **Completed**، ثم يُعاد إلى التطبيق ليعرضه للمستخدم مع إمكانية الاطلاع على التفاصيل التقنية.

يجري الاتصال بخدمتي VirusTotal وGemini من الخادم الخلفي فقط، ولا يتصل التطبيق بهما مباشرة، وهو ما يحمي مفاتيح الوصول (API Keys) وينظم تبادل البيانات.

## معمارية النظام

صُمم النظام بمعمارية متعددة الطبقات تفصل الواجهة عن منطق الأعمال والخدمات الخارجية:

| الطبقة | دورها |
|---|---|
| طبقة المستخدم | استقبال مدخلات المستخدم وعرض النتائج، دون أي منطق معالجة |
| طبقة التطبيق (Flutter) | إدارة الواجهة وإرسال الطلبات واستقبال الاستجابات وعرض التقارير |
| طبقة الخادم الخلفي (Cloudflare Workers + Hono) | التحقق من المستخدم، وإدارة بيانات الفحص، والتعامل مع قاعدة البيانات، والتنسيق مع الخدمات الخارجية |
| طبقة الخدمات الخارجية | VirusTotal API للفحص، وGoogle Gemini API لتوليد التقرير المبسط |

## البيئة التقنية

### تطبيق الهاتف

- **Flutter** بلغة Dart، مع تنظيم الشيفرة في طبقات: Core وModels وServices وProviders.
- **Riverpod** لإدارة الحالة وفصل منطق الأعمال (المصادقة، الفحص، السجل) عن الواجهة.
- **GoRouter** لتوجيه مركزي يبدأ من الشاشة الترحيبية ويحول المستخدم إلى تسجيل الدخول أو الواجهة الرئيسية حسب حالة المصادقة، ويمنع الوصول إلى الشاشات المحمية دون صلاحية.
- **Dio** للاتصال بالخادم بصيغة JSON، مع اعتراضات (Interceptors) ومعالجة مركزية لأخطاء الشبكة مثل انتهاء المهلة وانقطاع الاتصال.
- **Flutter Secure Storage** لحفظ رموز الوصول وبيانات الجلسة مشفرة عبر Android Keystore بدل تخزينها كنص واضح.

### الخادم الخلفي والبيانات

| المكون | الوظيفة في المشروع |
|---|---|
| Cloudflare Workers | بيئة تشغيل عديمة الخوادم على شبكة الحافة لمعالجة الطلبات |
| Hono | بناء واجهات REST وتوجيه المسارات وتطبيق الوسطاء (Middleware) |
| Middleware | اعتراض الطلبات والتحقق من رمز JWT ومعالجة الأخطاء |
| Cloudflare D1 | قاعدة بيانات علائقية مبنية على SQLite لحفظ المستخدمين والفحوصات والنتائج |
| Cloudflare KV | تخزين مؤقت بنمط مفتاح وقيمة لتقليل الطلبات المتكررة إلى الخدمات الخارجية |
| JWT | مصادقة عديمة الحالة؛ يُرفق الرمز بترويسة Authorization في كل طلب |

### نموذج البيانات

تتكون قاعدة البيانات من خمسة جداول مترابطة يتوسطها جدول الفحوصات:

| الجدول | محتواه |
|---|---|
| Users | بيانات المستخدم الأساسية وكلمة المرور مشفرة؛ يرتبط بالفحوصات بعلاقة واحد إلى متعدد |
| Scans | كل عملية فحص: نوعها، والقيمة المستهدفة، وحالتها، وتاريخها |
| VT_Results | أعداد المحركات حسب التصنيف، ورابط التقرير الأصلي، والاستجابة الخام بصيغة JSON |
| AI_Analyses | مستوى الخطورة، والملخص المبسط، والإرشادات الوقائية، وتاريخ التقرير |
| File_Metadata | اسم الملف وحجمه ونوعه وبصمته الرقمية، دون حفظ الملف نفسه |

## واجهات التطبيق

| الشاشة | الوظيفة |
|---|---|
| الواجهة الرئيسية | الحالة العامة للجهاز، وخيارا فحص الملفات والروابط، وآخر الفحوصات |
| فحص الروابط | إدخال الرابط مع خيارات مثل الاقتصار على روابط HTTPS واختيار اللغة |
| نتيجة الفحص | حالة الرابط، والملخص الأمني، والنصائح الوقائية، وتفاصيل VirusTotal، وإمكانية فتح الرابط بعد التأكد من سلامته |
| سجل الفحوصات | جميع الفحوصات السابقة مع البحث والتصفية وحالة كل فحص (آمن أو خبيث) |
| الملف الشخصي | بيانات المستخدم وإحصائيات مثل عدد الروابط والملفات المفحوصة والتهديدات المكتشفة |
| الإعدادات | تعديل الملف الشخصي، والإشعارات، والخصوصية والأمان، ومفاتيح مزودي خدمات الفحص، ولغة التطبيق، وتسجيل الخروج |

ويحدد تصميم النظام دورًا لمدير النظام يقتصر على إدارة حسابات المستخدمين ومراقبة استهلاك واجهات البرمجة، دون التدخل في عمليات الفحص نفسها.

## النتائج الموثقة

يذكر الكتاب أن التطبيق نجح في تنفيذ فحص الملفات والروابط وعرض النتائج بوضوح، مع الاحتفاظ بسجل الفحوصات وإدارة الحسابات والإعدادات ضمن واجهة سهلة. ومن أهم ما أنجزه المشروع:

- دمج VirusTotal لتنفيذ الفحص متعدد المحركات والاستفادة من نتائجه.
- توظيف Google Gemini لتوليد ملخصات أمنية مبسطة وتوصيات وقائية.
- خادم خلفي على Cloudflare Workers مع D1 لإدارة البيانات وKV لتسريع الوصول إليها.
- مصادقة آمنة لجلسات المستخدم باستخدام JWT.

لا يتضمن الكتاب قياسات كمية لنسبة الكشف أو الإنذارات الكاذبة أو زمن الاستجابة أو استهلاك البطارية. وقد حُدد زمن استجابة لا يتجاوز 3 ثوانٍ للاستعلامات المتكررة **هدفًا** في نطاق المشروع، لا نتيجة مقيسة. كما أن نسب الدقة الواردة في الكتاب تعود إلى دراسات سابقة استُعرضت في الإطار النظري، وليست نتائج لهذا التطبيق.

## حدود النسخة الحالية

- يعمل التطبيق على **Android فقط** في هذه المرحلة، دون دعم iOS.
- يقتصر على **التحليل الثابت** المعتمد على نتائج VirusTotal، دون تحليل ديناميكي لسلوك الملفات أو مراقبة حركة الشبكة أو حماية فورية على الجهاز.
- دقة الكشف مستمدة من محركات VirusTotal، ويتطلب الفحص اتصالًا بالإنترنت وتوفر الخدمات السحابية الخارجية.
- التقرير المبسط يولده نموذج لغوي عام، لذا يبقى ملخصًا إرشاديًا يُستحسن أن يُقرأ مع تفاصيل نتائج المحركات.
- قُيّم النظام ضمن بيئة محلية محدودة، دون تقييم معياري موثق مقارنة بأنظمة أخرى.

## تطويرات مستقبلية محتملة

بحسب الآفاق الواردة في المشروع، يمكن توسيع CyberShield عبر:

- دعم فحص أنواع إضافية من الملفات والوسائط الرقمية.
- دمج مزودي فحص أمني آخرين إلى جانب VirusTotal لزيادة موثوقية النتائج.
- تطوير نموذج ذكاء اصطناعي متخصص في تفسير نتائج الفحص بدل الاعتماد على النماذج العامة.
- إشعارات فورية عند اكتشاف تهديدات جديدة أو تحديث نتائج الفحص.
- دعم أنظمة تشغيل إضافية مع تجربة استخدام موحدة.
- لوحة تحكم إدارية متقدمة لمراقبة الاستخدام وتحليل الإحصائيات.
- عمل بعض الوظائف دون اتصال مع مزامنة البيانات عند عودة الاتصال.
- تحليل سلوكي وكشف مبكر للتهديدات، وربط النظام بمنصات الحماية المؤسسية وأنظمة SIEM.

## ملاحظة حول الخصوصية

يحفظ التطبيق بيانات الحساب وسجل الروابط المفحوصة وبيانات وصفية للملفات، ويرسل الروابط وبصمات الملفات إلى خدمات خارجية. لذلك يحتاج أي استخدام فعلي إلى سياسة واضحة لما يُرسل إلى VirusTotal وGemini، ولمدة الاحتفاظ بسجل الفحوصات وصلاحيات الوصول إليه.

## هل تخطط لنظام مشابه؟

إذا كنت تعمل على أداة أمنية لفحص الملفات والروابط بالذكاء الاصطناعي وتحتاج إلى مساعدة تقنية في تطوير الفكرة أو بناء نموذج أولي، يمكن التواصل مع **مكتب تكنو إنجاز** لمناقشة متطلبات المشروع ونطاق الدعم المناسب.
