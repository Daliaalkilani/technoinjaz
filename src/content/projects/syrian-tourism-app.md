# تطبيق سياحي ذكي لتعزيز السياحة في سوريا

مشروع أكاديمي لتطوير **تطبيق سياحي رقمي لتعزيز السياحة الداخلية في سوريا**، نفذه فريق من الطلاب بمساعدة ودعم تقني من **مكتب تكنو إنجاز**. يجمع التطبيق في منصة واحدة استكشاف الوجهات السياحية المصنفة، ودليل المدينة ونصائح السفر، وحجز الفنادق وغرفها، ومتجرًا رقميًا للمنتجات الحرفية السورية، ومدونة ومقالات سياحية، وتجارب الزوار، مع المفضلة والتنبيهات.

بُني تطبيق الهاتف بإطار **Flutter** ولغة Dart، والجانب الخلفي وواجهات API ولوحة الإدارة بإطار **Laravel** وفق نمط MVC، مع قاعدة بيانات **MySQL** علائقية. ويخدم النظام ثلاثة أدوار رئيسية: **السائح** و**الحرفي** و**مدير النظام**. النتيجة الموثقة نموذج تطبيقي عامل بواجهات هاتف ولوحة إدارة، دون بيانات تشغيلية عن أثر اقتصادي أو زيادة فعلية في السياحة.

## حقائق المشروع

| العنصر | البيانات |
|---|---|
| نوع المشروع | منصة سياحية رقمية: تطبيق هاتف ولوحة تحكم إدارية |
| المجال | السياحة الذكية، تطبيقات الهاتف، التجارة الإلكترونية للحرف اليدوية |
| حالة المشروع | نموذج تطبيقي منفذ، مع اختبارات وظيفية أولية |
| دور تكنو إنجاز | دعم ومساعدة تقنية للطلاب أثناء تطوير المشروع |
| تقنيات أساسية | Flutter / Dart، Laravel / PHP، MySQL، Eloquent ORM، REST API، Bootstrap، JavaScript، خادم Apache |
| المخرجات | تطبيق سائح وحرفي، متجر حرف يدوية بسلة وطلبات، حجز فنادق، محتوى سياحي، لوحة إدارة شاملة |

## المشكلة التي يعالجها المشروع

يعرض المشروع أن السياحة في سوريا تراجعت بشدة بعد عام 2011، ثم بدأت بالتعافي، إذ تذكر بيانات وزارة السياحة التي يستشهد بها نحو 4.55 مليون زائر في عام 2024. وفي المقابل يفتقر السوق المحلي إلى منصة رقمية شاملة توفر محتوى محدثًا يغطي تنوع المواقع الأثرية والطبيعية والدينية، وأدوات تساعد الزائر على اتخاذ قراراته، فيلجأ إلى مصادر متفرقة.

كما يواجه الحرفيون المحليون صعوبة في الوصول إلى السائح. لذلك سعى المشروع إلى بناء تطبيق واحد يجمع الدليل السياحي، والحجز، والمحتوى التثقيفي، وتجارب الزوار، وسوقًا رقمية للحرف اليدوية، بحيث يخطط المستخدم رحلته دون الرجوع إلى مصادر خارجية.

## دور مكتب تكنو إنجاز

نُفذ المشروع أكاديميًا بواسطة الطلاب، مع **مساعدة ودعم تقني من مكتب تكنو إنجاز أثناء مراحل التطوير**. ويُعرض ضمن أعمال المكتب مثالًا على دعمه للمشاريع التي تبني منصات متعددة الأطراف بتطبيق Flutter وخادم Laravel وقاعدة بيانات مترابطة.

## أدوار المستخدمين

يحدد مخطط حالات الاستخدام في المشروع ثلاثة أدوار:

| الدور | ما يستطيع فعله |
|---|---|
| السائح | استكشاف المواقع السياحية، وقراءة المقالات والتجارب، وتعديل ملفه الشخصي، وحجز الفنادق والأنشطة، والتقييم ومشاركة تجربته |
| الحرفي | إضافة منتجاته وتعديلها وحذفها في السوق الرقمية، ومتابعة طلبات الشراء، وقراءة المحتوى والتعليق على التجارب |
| مدير النظام | إدارة لوحة التحكم، ومراجعة المقالات قبل النشر، وإدارة المواقع والمستخدمين، والإشراف على الحجوزات والطلبات |

وتشترط العمليات الخاصة، مثل الحجز والشراء وإدارة المنتجات، تسجيل الدخول المسبق.

## واجهات تطبيق الهاتف

تشمل الواجهات النهائية الموثقة في المشروع:

- تسجيل الدخول، وواجهة الترحيب، والقائمة الرئيسية.
- **الوجهات السياحية** ووصف كل وجهة، و**تجارب الزوار** لكل وجهة.
- **دليل المدينة** و**نصائح وإرشادات السفر**.
- **الفنادق**، و**الفواتير والحجوزات** مع تفاصيل كل حجز.
- **المنتجات والحرف اليدوية**، وتفاصيل المنتج، و**سلة التسوق**، وتفاصيل عملية الطلب.
- **المدونة السياحية** والمقالات.
- **المفضلة** لحفظ المواقع والمنتجات والفنادق والمقالات.
- **التنبيهات والإشعارات** وإعداداتها.

والواجهة عربية افتراضيًا.

| القسم | ما يديره |
|---|---|
| لوحة التحكم | نظرة عامة على النظام |
| المستخدمون | عرض معلومات المستخدم وتعديلها |

| المواقع السياحية | فئات المواقع، والمواقع وتفاصيلها وتعديلها، والأنشطة السياحية |
| الفنادق | الفنادق، وأنواع الغرف، والغرف، وحجوزات الفنادق وتفاصيلها |
| المحتوى | تجارب المواقع السياحية، والمقالات وتفاصيلها وتعديلها |

## البنية التقنية وقاعدة البيانات

- **Flutter / Dart:** تطبيق متعدد المنصات من قاعدة شيفرة واحدة، ببنية طبقية تفصل العرض عن الخدمات والنماذج ومستودعات البيانات.
- **Laravel / PHP:** الجانب الخلفي وواجهات REST API ولوحة الإدارة وفق نمط MVC، مع Eloquent ORM للتعامل مع قاعدة البيانات.
- **Bootstrap وJavaScript:** واجهات لوحة الإدارة.
- **البنية التحتية:** خادم ويب Apache، وقاعدة بيانات MySQL مركزية.

صُممت قاعدة البيانات العلائقية حول الجداول التالية:

| المجال | الجداول |
|---|---|
| المستخدمون | Users مع نوع الحساب والدور، وUserProfiles منفصلًا عن بيانات الدخول، وUserPhoneNumbers لأكثر من رقم |
| المتجر | Products وProductCategories الهرمية، وShoppingCartItems، وProductOrders، وProductOrderItems |
| السياحة | TouristSites بالإحداثيات والصور والفيديو، وSiteCategories، وTouristActivities بالتوقيت والمدة وعدد المشاركين |
| الفنادق | Hotels، وHotelRoomTypes، وHotelRooms بالسعر والمساحة والتوافر، وHotelBookings بعدد الضيوف وحالة الحجز والدفع |
| المحتوى والتفاعل | Articles بحالات النشر، وSiteExperiences، وFavorites وRatings وComments ببنية متعددة الأهداف (target_type وtarget_id) |

وتعتمد العلاقات على مفاتيح أجنبية مع سياسات حذف مدروسة (cascade أو restrict أو set null) حسب حساسية البيانات، وحقول زمنية في معظم الجداول.

## نتائج الاختبار

تحقق الفريق من الوظائف الأساسية، واختبر قابلية الاستخدام لمختلف الفئات، ومرونة لوحة التحكم ودقة معالجة البيانات. ويصف المشروع النتائج بأنها **مبدئية**، تشير إلى استقرار المنصة وسلاسة التنقل بين الواجهات وسرعة الاستجابة في البحث وإدخال البيانات وتعديلها.

لا يقدم المشروع أرقامًا لزمن الاستجابة أو عدد المستخدمين المختبرين، ولا بيانات تشغيلية لقياس أثر اقتصادي أو زيادة فعلية في السياحة. أما الأرقام الواردة في مقدمته عن تطبيقات مثل Visit Jordan وVisit Singapore وTiqets فهي نتائج تلك التطبيقات، لا نتائج هذا المشروع.

## التحديات وحدود النسخة الحالية

- واجه الفريق صعوبات في ربط الواجهة الأمامية بالخلفية، وإدارة البيانات المعقدة لتصنيفات السياحة، والتنسيق بين بعض الواجهات، وعولجت بتقسيم العمل وتنظيم المهام.
- لا يتضمن النظام بوابات دفع إلكترونية دولية بعد؛ إذ يطرحها المشروع هدفًا لاحقًا.
- الواجهة عربية حاليًا، ودعم اللغات الأخرى من التطويرات المقترحة.
- النظام نموذج أكاديمي لم يُطلق للاستخدام العام.

## تطويرات مستقبلية محتملة

بحسب ما يقترحه المشروع:

- نظام توصية بالذكاء الاصطناعي يقترح الوجهات حسب اهتمامات السائح وتاريخ تصفحه أو شرائه.
- الواقع المعزز لتجربة افتراضية للمواقع قبل الزيارة أو محتوى تفاعلي عبر الكاميرا في الموقع.
- الربط مع بوابات الدفع الإلكترونية الدولية لتسهيل الحجز من خارج البلاد.
- واجهات بلغات متعددة، مثل الإنجليزية والفرنسية والروسية.
- توسيع التغطية لتشمل القرى النائية والمناطق الأقل شهرة سياحيًا.
- التعاون مع الجهات السياحية والثقافية لإثراء المحتوى بصور ثلاثية الأبعاد وخرائط تفاعلية.

## هل تخطط لنظام مشابه؟

إذا كنت تعمل على تطبيق سياحي أو منصة رقمية تجمع خدمات متعددة وتحتاج إلى مساعدة تقنية في تطوير الفكرة أو بناء نموذج أولي، يمكن التواصل مع **مكتب تكنو إنجاز** لمناقشة متطلبات المشروع ونطاق الدعم المناسب.
