# روبوت الدردشة الصوتية التقنية بالذكاء الاصطناعي

مشروع تطوير **روبوت دردشة تعليمي صوتي** يعمل مساعدًا تقنيًا للطلاب في البرمجة وهندسة الحاسوب والشبكات، نفذه فريق من الطلاب بمساعدة تقنية من **مكتب تكنو إنجاز**. يستقبل الروبوت سؤال المستخدم صوتيًا عبر واجهة ويب، ويحوله إلى نص، ثم يرسله إلى نموذج الذكاء الاصطناعي **Gemini-live-2.5-flash** من Google لتوليد إجابة سياقية تُعرض نصًا وتُنطق صوتًا، بينما يحرك محرك سيرفو ذراع الروبوت بالتزامن مع الرد.

يجمع المشروع بين ثلاثة مجالات في نظام واحد: **الذكاء الاصطناعي التوليدي ومعالجة اللغات الطبيعية (NLP)**، و**تقنيات الويب في الزمن الحقيقي** عبر خادم Node.js وبروتوكول WebSocket، و**إنترنت الأشياء والأنظمة المدمجة** عبر لوحة **NodeMCU ESP8266** ومحرك **MG995**. وأظهرت التجارب العملية نجاح المحادثة الصوتية وتزامن الرد مع حركة الذراع، دون أن يقدم التقرير قياسات رقمية لدقة الإجابات أو زمن الاستجابة.

## حقائق المشروع

| العنصر | البيانات |
|---|---|
| نوع المشروع | روبوت دردشة تعليمي صوتي مع تفاعل حركي |
| المجال | الذكاء الاصطناعي في التعليم، معالجة اللغات الطبيعية، إنترنت الأشياء |
| حالة المشروع | نموذج فيزيائي عامل جُرّب عمليًا في محادثات صوتية |
| دور تكنو إنجاز | دعم ومساعدة تقنية للطلاب أثناء تطوير المشروع |
| تقنيات أساسية | Gemini-live-2.5-flash (Gemini Live API)، JavaScript، Node.js، WebSocket، NodeMCU ESP8266، Servo MG995 |
| المخرجات | محادثة صوتية ونصية، ردود منطوقة (TTS)، حركة ذراع متزامنة، واجهة ويب مع سجل تصحيح |

## المشكلة التي يعالجها المشروع

يحتاج طلاب التخصصات التقنية إلى إجابات سريعة عن أسئلة البرمجة والمفاهيم التقنية خارج أوقات المحاضرات والدوام الرسمي، بينما ينشغل المدرسون بالرد على أسئلة متكررة وشائعة. ينتمي المشروع إلى مجال **الذكاء الاصطناعي في التعليم (AIEd)**، ويهدف إلى توفير مساعد رقمي متاح على مدار الساعة يفهم سياق السؤال لا كلماته المفتاحية فقط، ويشجع **التعلم الذاتي** عبر بيئة يطرح فيها الطالب أسئلته دون حرج.

ولإضفاء طابع أكثر واقعية على التفاعل، لم يقتصر المشروع على تطبيق محادثة برمجي، بل أضاف جسمًا فيزيائيًا للروبوت بذراع متحركة ومكبر صوت.

## أهداف المشروع

- تطوير روبوت دردشة يعمل مساعدًا تعليميًا تقنيًا ويقدم دعمًا معرفيًا فوريًا في المجالات البرمجية والتقنية.
- دعم التعلم الذاتي بتمكين الطلاب من الوصول إلى إجابات سريعة دون التقيد بأوقات الدوام.
- فهم نية الطالب وتحليل لغته باستخدام معالجة اللغات الطبيعية والنماذج اللغوية الكبيرة.
- تحقيق التكامل بين البرمجيات والعتاد عبر لوحة NodeMCU ESP8266 ومحرك سيرفو واحد يمنح الروبوت حركة أثناء الرد.
- إنشاء قاعدة معرفة تقنية تتضمن شروحات ومفاهيم برمجية.
- تطوير واجهة تفاعل متعددة الوسائط تدعم التواصل النصي والصوتي عبر تقنيات التعرف على الكلام.

## دور مكتب تكنو إنجاز

نُفذ المشروع أكاديميًا بواسطة الطلاب، مع **مساعدة ودعم تقني من مكتب تكنو إنجاز أثناء مراحل التطوير**. ويُعرض ضمن أعمال المكتب مثالًا على دعمه للمشاريع التي تربط النماذج اللغوية السحابية بالعتاد الإلكتروني وإنترنت الأشياء.

## آلية عمل الروبوت

يعمل النظام عبر مسارين متزامنين يلتقيان في الخادم المركزي:

1. يتحدث المستخدم إلى الروبوت عبر واجهة الويب في المتصفح.
2. تحول الواجهة الكلام إلى نص باستخدام تقنية **Speech-to-Text**.
3. يُرسل النص إلى الخادم المركزي (**Node.js**) عبر اتصال **WebSocket** في الزمن الحقيقي.
4. يمرر الخادم النص إلى **Gemini API** عبر HTTPS (المنفذ 443) لتوليد إجابة سياقية.
5. يعيد الخادم الرد إلى الواجهة بأسلوب **البث التدريجي (Streaming)**، فيُعرض نصًا ويُحوَّل إلى صوت مسموع بتقنية **Text-to-Speech**.
6. في المسار الفيزيائي، ترسل لوحة ESP8266 طلبات دورية إلى الخادم عبر **HTTP Polling** على الشبكة المحلية للاستعلام عن حالة الحركة المطلوبة.
7. يربط الخادم حالة المحادثة بالحركة، فتولّد اللوحة إشارات **PWM** تحرك ذراع الروبوت عبر محرك السيرفو بالتزامن مع الرد الصوتي.
8. يتيح زر تبديل (Switch) إرسال حالة التشغيل أو الإيقاف إلى الخادم.

## معمارية النظام

| الكتلة | الدور |
|---|---|
| واجهة المستخدم (Web Client) | استقبال الصوت وتحويله إلى نص، وعرض الرد وتحويله إلى كلام |
| الخادم المركزي (Node.js Backend) | إدارة الطلبات وتنظيم تدفق البيانات ومزامنة حالة الروبوت |
| خدمة الذكاء الاصطناعي (Google Gemini API) | معالجة النص وتوليد الإجابات بالنموذج اللغوي |
| العتاد الإلكتروني (ESP8266) | التحكم بحركة محرك السيرفو واستقبال أوامر التشغيل والإيقاف |

تستخدم الواجهة بروتوكول WebSocket مع الخادم لنقل البيانات لحظيًا، ويتواصل الخادم مع خوادم Google عبر HTTPS، بينما يتصل المتحكم بالخادم عبر HTTP Polling. وتدعم واجهة Gemini نمطين: REST API للطلبات القياسية بصيغة JSON، وLive API المعتمدة على WebSocket للاتصال ثنائي الاتجاه بزمن استجابة منخفض، مع إعدادات مثل Temperature وTop-K وTop-P للتحكم بطبيعة المخرجات.

## المكونات العتادية

| المكوّن | الدور والمواصفات الموثقة |
|---|---|
| NodeMCU ESP8266 | الاتصال اللاسلكي Wi-Fi (802.11 b/g/n) والتحكم بالسيرفو؛ معالج L106 32-bit بتردد 80–160 MHz وجهد تشغيل 3.3V |
| محرك سيرفو TowerPro MG995 | تحريك ذراع الروبوت؛ سيرفو رقمي بتروس معدنية، جهد 4.8–7.2V، عزم 10–12 kg/cm، دوران حتى 180 درجة |
| بطاريات ليثيوم أيون 18650 | مصدر الطاقة؛ جهد اسمي 3.6–3.7V وجهد شحن كامل 4.2V |
| منظم الجهد LM2596 | خفض الجهد وتوفير قيمة مستقرة للدارات؛ دخل 4.5–40V، خرج قابل للضبط 1.23–37V، تيار حتى 3A |
| نظام إدارة البطارية BMS | الحماية من الشحن الزائد والتفريغ العميق والتيار الزائد والقصر |
| محول AC-to-DC تبديلي | تحويل التيار المتردد إلى تيار مستمر لتغذية الدارات |
| مكبر صوت | إخراج الردود الصوتية |

يمر التيار من مصدر الطاقة إلى وحدة BMS للحماية، ثم إلى منظم LM2596 لخفض الجهد، ويتصل السيرفو بلوحة ESP8266 بخطوط الطاقة والإشارة مع أرضي مشترك بين جميع المكونات. وصُمم الهيكل الخارجي من أجزاء خفيفة تخفي المكونات الإلكترونية مع إبقاء الوصول إليها سهلًا للصيانة.

## واجهة المستخدم

صُممت واجهة ويب بسيطة لإجراء المحادثات الصوتية ومتابعة حالة النظام لحظيًا، وتضم:

- قسمًا لعرض النص المحوَّل من الصوت.
- منطقة لعرض رد المساعد الذكي.
- أزرار التحكم بالصوت والاتصال.
- أدوات للتحكم بحالة الروبوت وتشغيله أو إيقافه.
- نافذة سجل تصحيح (Debug Log) لمتابعة الاتصال والعمليات الداخلية، مع عرض حالة الاتصال بخدمة Gemini Live.

## النتائج الموثقة

أظهرت التجارب العملية للنموذج ما يلي:

- نجاح الاتصال بين الواجهة والخادم عبر WebSocket في الزمن الحقيقي.
- نجاح تحويل الكلام إلى نص واستقبال الأوامر الصوتية مباشرة عبر المتصفح.
- استقبال ردود Gemini API بصورة مستقرة وتحويلها إلى صوت مسموع.
- تحقيق تزامن بين الرد الصوتي وحركة ذراع الروبوت.
- استقبال ESP8266 أوامر الحركة عبر HTTP Polling وتنفيذها، مع استقرار عمل السيرفو دون اهتزازات كبيرة أو انقطاع في الإشارة.
- توفير جهد مستقر للمكونات عبر LM2596 ودارة BMS.

هذه نتائج **وظيفية للنموذج الأولي**. لم يعرض التقرير قيمًا كمية لدقة الإجابات أو زمن الاستجابة أو عدد الأسئلة المختبرة، لذلك لا تُنسب للنظام نسب دقة غير موثقة.

## حدود النسخة الحالية

- يعتمد النظام كليًا على المعالجة السحابية واتصال الإنترنت، ولا يعمل دون اتصال.
- يقتصر الجانب الحركي على ذراع واحدة يحركها سيرفو واحد، دون تنقل أو حركات معقدة.
- لا يتضمن كاميرا أو تعرفًا على الوجوه أو تحليلًا للمشاعر؛ فالتفاعل نصي وصوتي فقط.
- النظام موجّه للدعم التعليمي التقني، ولا يقدم استشارات طبية أو قانونية أو نفسية، ولا يُستخدم لإدارة الاختبارات أو إصدار تقييمات رسمية.
- لا يحتفظ بذاكرة حوار طويلة المدى في النسخة الحالية، وهي مذكورة ضمن التطويرات المستقبلية.

## تطويرات مستقبلية محتملة

بحسب الآفاق الواردة في المشروع:

- تحريك أجزاء إضافية مثل الذراعين أو العينين لزيادة التفاعل الحركي.
- تحسين دقة التعرف على الكلام ودعم لهجات متعددة.
- إضافة ذاكرة محادثات تحفظ سياق الحوار لفترات أطول.
- تطوير نسخة تعمل دون اتصال كامل بالإنترنت باستخدام نماذج ذكاء اصطناعي محلية.
- دعم الكاميرات والرؤية الحاسوبية للتعرف على الوجوه أو تحليل الإيماءات.
- توسيع قاعدة المعرفة لتشمل مجالات تعليمية خارج التخصصات التقنية.
- تطبيق للهواتف الذكية، وتحسين الهيكل الفيزيائي بالطباعة ثلاثية الأبعاد.

## هل تخطط لنظام مشابه؟

إذا كنت تعمل على روبوت دردشة أو مساعد ذكي يعتمد على النماذج اللغوية والصوت وتحتاج إلى مساعدة تقنية في تطوير الفكرة أو بناء نموذج أولي، يمكن التواصل مع **مكتب تكنو إنجاز** لمناقشة متطلبات المشروع ونطاق الدعم المناسب.
