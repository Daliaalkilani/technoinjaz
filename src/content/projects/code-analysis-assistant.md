# مساعد برمجي لتحليل الشيفرات البرمجية وتقييم نماذج توليد الكود

مشروع أكاديمي نفذه فريق من الطلاب بمساعدة تقنية من **مكتب تكنو إنجاز** لبناء منصة باسم **EHCode Hub**، تعمل **حاضنةَ تقييم (Benchmark Harness)** لمقارنة نماذج الذكاء الاصطناعي في توليد الكود، وتضم في الوقت نفسه **مساعدًا برمجيًا ذكيًا** ومحرر أكواد يحلل الشيفرات ويصحّحها ويحوّلها بين اللغات. قارنت المنصة ثلاثة نماذج: **GLM-5.1** من Zhipu AI، و**DeepSeek V4 Pro**، و**MiMo V2.5 Pro** من Xiaomi، عبر 20 مهمة برمجية موحدة في عشر فئات تطويرية.

بُني خادم المنصة بـ **Node.js** معتمدًا على وحداته المدمجة فقط دون أي اعتماديات خارجية، مع واجهة عربية بـ HTML5 وCSS3 وJavaScript الخام، ودُمج المساعد **EHCode** المبني على الوكيل مفتوح المصدر **opencode** عبر iframe. أنتجت النماذج الثلاثة 60 مشروعًا، وتصدّر GLM-5.1 التقييم بمجموع موزون 8.78 من 10، يليه DeepSeek V4 Pro بـ 8.75 ثم MiMo V2.5 Pro بـ 7.96.

| العنصر | البيانات |
|---|---|
| نوع المشروع | منصة لتقييم نماذج توليد الكود مع مساعد برمجي ذكي |

| السنة | 2025–2026 |

| المخرجات | عارض تفاعلي للمشاريع، تشغيل تلقائي، دليل لكل مشروع، جدول مقارنة النماذج، محرر أكواد ذكي، مساعد EHCode بواجهتي ويب وسطر أوامر |

## المشكلة التي يعالجها المشروع

مع انتشار النماذج اللغوية الكبيرة في كتابة الأكواد، يصعب على المطورين والمؤسسات اختيار النموذج الأنسب، لأن التقييمات الشائعة إما محدودة النطاق، أو تعتمد على مقاييس آلية لا تعكس جودة المخرجات الفعلية في مشاريع حقيقية. كما أن النماذج قد تتفوق في الواجهات الأمامية وتضعف في الخلفية أو تطبيقات الجوال.

ويضيف المشروع مشكلات عملية: تشغيل المشاريع المولّدة يدويًا يستهلك وقتًا في تثبيت الاعتماديات وتحرير المنافذ، وكثير من هذه المشاريع بلا توثيق، وبيئات التقييم الحالية لا تتيح مساعدًا برمجيًا يساعد على فهم الكود أثناء التقييم. لذلك جاءت فكرة منصة واحدة تجمع الفحص التلقائي والعرض والتشغيل والتوثيق والمقارنة والمساعدة البرمجية.

## أهداف المشروع

- تصميم 20 مهمة برمجية موحدة تغطي عشر فئات: تطبيقات الويب المتكاملة، وواجهات API، والواجهات الأمامية، وتطبيقات Python، والتجارة الإلكترونية، وتصور البيانات، والنمذجة ثلاثية الأبعاد، وتطبيقات الجوال بـ Flutter، وأدوات الأتمتة.
- بناء خادم عارض خفيف بلا اعتماديات خارجية يكتشف نوع كل مشروع ونقطة دخوله ومنفذه تلقائيًا.
- تشغيل أي مشروع بنقرة، مع تثبيت الاعتماديات وتحرير المنافذ وعرض الناتج داخل iframe.
- توليد دليل تشغيل لكل مشروع، ودمج مساعد برمجي داخل المنصة.
- جدول مقارنة موضوعي يعرض مؤشرات النماذج ويقدّم توصية.
- مشغّل موحد يقلع المنصة كاملة بنقرة واحدة على Windows.

## دور مكتب تكنو إنجاز

نُفذ المشروع أكاديميًا بواسطة الطلاب، مع **مساعدة ودعم تقني من مكتب تكنو إنجاز أثناء مراحل التطوير**. ويُعرض ضمن أعمال المكتب مثالًا على دعمه لمشاريع أدوات المطورين والتطبيقات المبنية على النماذج اللغوية الكبيرة.

## آلية عمل المنصة

1. يفحص خادم العارض مجلد `/models` ويصنّف كل مشروع حسب ملفاته: `package.json` لمشاريع Node.js، و`requirements.txt` لمشاريع Python، و`pubspec.yaml` لمشاريع Flutter، وما عدا ذلك مشروع ثابت.
2. تُعرض النماذج في أقسام، ولكل مشروع بطاقة تبيّن اسمه ووصفه ونوعه ومنفذه وحالته.
3. عند الضغط على "فتح المشروع" يستقبل الخادم الطلب عبر `/api/launch`، ويوقف أي مشروع آخر لتحرير المنفذ.
4. يُخدَم المشروع الثابت مباشرة، ويُنفَّذ `npm install` ثم `node` لمشاريع Node.js، و`pip install` ثم `python` لمشاريع Python، أما مشاريع Flutter فيوجَّه المستخدم لتشغيلها يدويًا بسبب تعقيد بيئتها.
5. تستقصي الواجهة جاهزية الخادم عبر `/api/probe` كل 1.5 ثانية حتى 20 محاولة، ثم تحمّل المشروع في iframe أو تعرض سبب الفشل.
6. يتتبع مدير العمليات حالة كل مشروع (سكون، بدء، تشغيل، انهيار، توقف)، ويسجّل الأخطاء، ويحرّر المنفذ فور انتهاء العملية.

## مكونات المنصة

| المكوّن | الوظيفة |
|---|---|
| خادم العارض (المنفذ 8800) | فحص المشاريع وتشغيلها وخدمة الواجهة، باستخدام وحدات http وfs وpath وurl وchild_process فقط |
| مساعد EHCode (المنفذ 8801) | واجهة دردشة مبنية على `opencode web` ومضمّنة عبر iframe، مع اختيار النموذج وإدارة الجلسات |
| محرر الأكواد الذكي | أزرار Solve وFix وConvert وAsk وتحليل الكود، مع تمييز بناء الجملة وأرقام الأسطر |
| محرك تحويل PHP إلى Laravel | إعادة تنظيم مشروع PHP وفق بنية Laravel (Routes وControllers وModels وMigrations وBlade)، مع تشغيل النسختين ونافذة مخرجات مباشرة |
| صفحة مقارنة النماذج | جدول مؤشرات وجدول معايير جودة موزونة مع إعلان النموذج الفائز |
| المشغّل الموحد start.bat | يتحقق من node وopencode، ويحرّر المنفذين 8800 و8801، ويقلع العارض والمساعد ثم يفتح المتصفح، مع stop.bat لإيقافهما |
| توزيعة EHCode المحمولة | ملف ehcode.exe مستقل لا يحتاج Node.js، مع install.bat يفعّل Playwright MCP |

ويتوفر المساعد بواجهة ويب وواجهة سطر أوامر (CLI). وفي محرر الأكواد عُرض مثال لتحويل شيفرة من Python إلى C++، ومثال لتقرير تحليل يشرح وظيفة الكود ويقترح تحسينات للجودة وقابلية الصيانة.

## النتائج الموثقة

### توزيع المشاريع المولدة

أنتج كل نموذج 20 مشروعًا، وكانت ملفات التشغيل `start.bat` متوفرة وسليمة في جميع المشاريع (20/20 لكل نموذج):

| المؤشر | GLM-5.1 | DeepSeek V4 Pro | MiMo V2.5 Pro |
|---|---|---|---|
| مشاريع Node.js | 3 | 3 | 4 |
| مشاريع Python | 2 | 0 | 2 |
| مشاريع ثابتة | 13 | 17 | 12 |
| مشاريع Flutter | 2 | 0 | 2 |
| مشاريع فيها ملف README | 5 | 1 | 2 |

ومن أبرز الملاحظات أن DeepSeek V4 Pro أنتج صفحات HTML بدل تطبيقات Flutter في مهمتي الجوال، بينما أنتج GLM-5.1 وMiMo V2.5 Pro تطبيقات Flutter حقيقية كما طُلب.

### تقييم معايير جودة البرمجيات

قُيّمت النماذج على ثمانية معايير بأوزان نسبية: الجودة الوظيفية، والأداء، والاعتمادية، والأمان، وسهولة الاستخدام، وقابلية الصيانة، وكفاءة التكلفة، وقابلية النقل:

| النموذج | أبرز الدرجات (من 10) | المجموع الموزون |
|---|---|---|
| GLM-5.1 | الجودة الوظيفية 9.2، سهولة الاستخدام 9.0، قابلية الصيانة 9.2 | 8.78 |
| DeepSeek V4 Pro | الأداء 9.2، الاعتمادية 9.0، الأمان 8.8، كفاءة التكلفة 9.5 | 8.75 |
| MiMo V2.5 Pro | قابلية النقل 9.0، مع أداء متوازن في بقية المعايير | 7.96 |

بناءً على ذلك أوصى المشروع بـ GLM-5.1 للاستخدام العام، وبـ DeepSeek V4 Pro للمشاريع التي تركز على الواجهة الخلفية، وبـ MiMo V2.5 Pro لمشاريع الواجهات الأمامية. كما أثبتت المنصة قدرتها على إدارة العمليات وتحرير المنافذ وتشغيل المشاريع تلقائيًا، ومن الأمثلة الموثقة تشغيل منصة تدوين وكرة أرضية ثلاثية الأبعاد من مشاريع GLM-5.1.

## حدود النسخة الحالية

- يذكر المشروع نفسه أن تسجيل الدرجات وتحديث بيانات النتائج ما زالا خطوة لازمة لإتمام التقييم الكمي، ولا يفصّل الكتاب طريقة منح الدرجات أو أوزان المعايير.
- المقارنة مبنية على 20 مهمة وثلاثة نماذج فقط، بمشروع واحد لكل مهمة من كل نموذج.
- لا تُشغَّل مشاريع Flutter تلقائيًا داخل المنصة.
- المنصة مصممة لـ Windows حاليًا، ودعم Linux وmacOS ضمن الخطط.
- المساعد لا يستلم سياق المشروع المفتوح تلقائيًا بعد.
- تختلف أرقام توزيع المشاريع الإجمالية في ملخص الكتاب قليلًا عن الجدول التفصيلي لكل نموذج، والجدول أعلاه مأخوذ من فصل المقارنة.

## تطويرات مستقبلية محتملة

بحسب الآفاق الواردة في المشروع، يمكن تطوير المنصة عبر:

- إضافة نماذج مثل GPT وClaude وGemini وQwen وGrok، ومهام أعقد مثل الأنظمة الموزعة وتطبيقات البلوكشين وتحليل البيانات الضخمة.
- تمرير سياق المشروع المفتوح إلى المساعد، وتواصل ثنائي الاتجاه بين العارض والمساعد عبر postMessage.
- أتمتة التقييم الكمي متعدد الأبعاد (قابلية التشغيل، وجودة الكود، والجودة البصرية، واكتمال المتطلبات) وحفظ النتائج في results.json مع لوحة إحصائية.
- استبدال الاستقصاء بـ WebSocket، وإضافة التخزين المؤقت والبحث والتصفية.
- دعم Linux وmacOS، وواجهة متعددة اللغات، ونسخة سحابية، ونشر المنصة مفتوحة المصدر مع واجهات API للإضافات.
- دمج معايير مرجعية عالمية مثل HumanEval وMBPP وSWE-bench، واستخدام المنصة تعليميًا مع ميزة "التحدي" بين الطلاب والنماذج.

## هل تخطط لنظام مشابه؟

إذا كنت تعمل على أداة ذكية لتحليل الشيفرات البرمجية وتحتاج إلى مساعدة تقنية في تطوير الفكرة أو بناء نموذج أولي، يمكن التواصل مع **مكتب تكنو إنجاز** لمناقشة متطلبات المشروع ونطاق الدعم المناسب.
