# أداة API وMCP لتحويل Markdown إلى PDF

مشروع أكاديمي نفذه فريق من الطلاب بمساعدة تقنية من **مكتب تكنو إنجاز** لتصميم وتنفيذ **خدمة سحابية لتحويل مستندات Markdown إلى ملفات PDF** تعمل بالكامل على بنية **Serverless** في منصة **Cloudflare**. تعالج الخدمة ثلاث نقاط تتعثر فيها كثير من أدوات التحويل: **دعم العربية واتجاه الكتابة من اليمين إلى اليسار (RTL)**، و**دمج مخططات PlantUML كرسوميات متجهة SVG** بدل الصور النقطية، و**عرض معادلات LaTeX** عبر KaTeX.

تُتاح الخدمة بثلاث طرق: **واجهة ويب** بمحرر ومعاينة مباشرة، و**واجهة برمجة تطبيقات REST** موثقة للمطورين، و**خادم MCP** (Model Context Protocol) يتيح لوكلاء الذكاء الاصطناعي استدعاء التحويل مباشرة. ويجري توليد ملف PDF النهائي داخل متصفح Chromium رأسي عبر **Cloudflare Browser Rendering (Puppeteer)**، وقد نجحت اختبارات المشروع الوظيفية في تحويل التنسيقات الأساسية والنص العربي والمعادلات وتلوين الشيفرات وثلاثة أنواع من مخططات PlantUML.

## المشكلة التي يعالجها المشروع

أصبحت لغة Markdown معيارًا شائعًا لكتابة الوثائق التقنية وفق منهجية «الوثائق كنصوص برمجية» (Docs-as-Code)، لكن تحويلها إلى PDF احترافي ما يزال يواجه عقبات واضحة:

- **ضعف دعم العربية:** تفشل كثير من محركات التحويل في تطبيق قواعد النصوص ثنائية الاتجاه (BiDi)، فينعكس ترتيب الكلمات ويختلط النص العربي بالشيفرات البرمجية.
- **المخططات والمعادلات:** تُحوَّل مخططات PlantUML غالبًا إلى صور نقطية منخفضة الدقة، وقد تُتجاهل معادلات LaTeX أو تُعرض خطأً.
- **عبء الخوادم:** تعتمد أدوات كثيرة على خوادم تقليدية تفرض تكاليف تشغيل وصيانة وتحد من التوسع التلقائي.

## دور مكتب تكنو إنجاز

نُفذ المشروع أكاديميًا بواسطة فريق من الطلاب، مع **مساعدة ودعم تقني من مكتب تكنو إنجاز أثناء مراحل التطوير**. ويُعرض ضمن أعمال المكتب مثالًا على دعمه لمشاريع الخدمات السحابية بدون خوادم وواجهات البرمجة وتكاملات MCP مع أدوات الذكاء الاصطناعي.

## كيف يحوّل النظام Markdown إلى PDF؟

1. يصل الطلب من واجهة الويب أو من REST API أو من خادم MCP، ومعه نص Markdown وإعدادات التحويل.
2. تتحقق الواجهة الخلفية المبنية بإطار **Hono** من هوية المستخدم عبر **JWT** عند الحاجة، ومن صحة المدخلات عبر **Zod**، وتوقف العملية برسالة خطأ إن وُجد خلل.
3. تستخرج مكتبة **Gray-matter** البيانات الوصفية (Frontmatter) مثل العنوان والمؤلف والكلمات المفتاحية.
4. تحوّل مكتبة **Marked** المستند إلى HTML، وتلوّن **Highlight.js** الكتل البرمجية، وتحوّل **KaTeX** معادلات LaTeX إلى HTML وCSS.
5. تُرمَّز مخططات PlantUML بـ PlantUML Encoder وتُرسل إلى خادم PlantUML، ثم يُدمج الرد داخل الصفحة بصيغة **Inline SVG**.
6. تُرسل صفحة HTML الموحدة إلى **Cloudflare Browser Rendering**، فيحمّلها متصفح Chromium الرأسي ويطبق الخطوط وCSS وإعدادات الطباعة وينشئ ملف PDF مع إظهار الخلفيات.
7. تُسجَّل العملية في قاعدة **D1** (وقت التنفيذ والحالة)، ويُعاد الملف مباشرة أو بصيغة Base64 حسب نوع الواجهة المستخدمة.

## المعمارية والمكونات

اعتمد النظام معمارية متعددة الطبقات تعمل كلها على حافة شبكة Cloudflare:

| الطبقة | المكونات | الدور |
|---|---|---|
| العميل | واجهة ويب بـ HTML وCSS وJavaScript، أنظمة خارجية، وكلاء ذكاء اصطناعي | إرسال المستندات واستلام ملفات PDF |
| الواجهة الخلفية | Hono على Cloudflare Pages Functions، Zod، JWT، bcryptjs | التوجيه والمصادقة والتحقق من البيانات وإدارة الطلبات |
| محرك التحويل | Gray-matter، Marked، Highlight.js، KaTeX، PlantUML Encoder | تحويل Markdown إلى صفحة HTML متكاملة |
| الخدمات السحابية | Cloudflare Browser Rendering، Cloudflare D1، خادم PlantUML | توليد PDF، وتخزين البيانات، وتوليد رسوميات SVG |

اختيرت تقنيات الويب الأساسية (Vanilla) للواجهة بدل أطر مثل React أو Vue لتقليل حجم الملفات وتسريع التحميل، مع خط **Noto Sans Arabic** للنصوص العربية وخط **Fira Code** للشيفرات. أما قاعدة **D1** المبنية على SQLite فتضم جداول المستخدمين والأدوار والملفات الشخصية ورموز التجديد (Refresh Tokens) والمستندات وإعدادات التحويل والسمات وسجل استخدام الواجهة البرمجية.

## واجهات النظام

- **الصفحة الرئيسية:** دخول بحساب أو كضيف، واختيار لغة الواجهة (عربية أو إنجليزية)، وتحديد اتجاه النص RTL أو LTR، والوصول إلى سجل التحويلات وتوثيق API.
- **محرر التحويل:** محرر Markdown بجانب معاينة فورية تستخدم محرك التحويل نفسه، مع قوالب جاهزة وتغيير ألوان السمة، ورفع ملفات .md بالسحب والإفلات، وزر «تحويل إلى PDF».
- **وضع الضيف:** يسمح بالتحويل دون حساب، ويحتفظ بالسجل داخل جلسة التصفح الحالية فقط.
- **دليل Markdown السريع:** مرجع مدمج لأوامر العناوين والقوائم والروابط والشيفرات.
- **توثيق API تفاعلي:** نقاط النهاية وطرق HTTP والمعاملات وأنواعها، بما فيها واجهات التسجيل وتسجيل الدخول، مع عرض الميزات مثل صفحة الغلاف وتعدد السمات.

## تكامل MCP مع وكلاء الذكاء الاصطناعي

نُفذ **خادم MCP** فوق Cloudflare Pages باستخدام نقل **Streamable HTTP**، بنقطة نهاية موحدة يستطيع أي عميل متوافق مع البروتوكول استخدامها. ويوفر الخادم أدوات لتحويل Markdown إلى PDF، واستعراض المستندات المحفوظة، وجلب مستند محدد، وإنشاء جلسات مؤقتة للمستخدمين الضيوف. كما يتضمن المشروع ملف **OpenClaw Skill** يصف إمكانات الخدمة ومعاملاتها لتستدعيها أدوات الذكاء الاصطناعي مباشرة.

## النتائج الموثقة

أجرى المشروع اختبارات وظيفية على مستندات تجريبية، وأظهرت:

| الاختبار | ما جرى اختباره | النتيجة الموثقة |
|---|---|---|
| خصائص النظام | RTL، المعاينة الفورية، تصدير PDF، المعادلات، تلوين الشيفرات، PlantUML | جميعها تعمل دون إعدادات إضافية |
| التنسيقات الأساسية | العناوين، العريض والمائل، القوائم المرتبة وغير المرتبة، الروابط | حُوّلت دون تشوه في التخطيط أو اتجاه النص |
| المعادلات (LaTeX) | معادلات سطرية ومستقلة ومصفوفات وتعبيرات معقدة | عُرضت مع الحفاظ على الرموز وأحجامها ومواضعها |
| تلوين الشيفرات | JavaScript وPython وCSS وSQL وJSON | طُبق التمييز النحوي لكل لغة داخل PDF |
| مخططات PlantUML | مخطط تسلسلي، مخطط فئات، مخطط تدفق | حُوّلت إلى رسوميات SVG متجهة دون صور نقطية |

هذه نتائج **تحقق وظيفي** موثقة بلقطات من المخرجات. لم يقس التقرير أزمنة الاستجابة أو سعة التحمل أو عدد التحويلات المختبرة، ولذلك لا تُنسب للخدمة أرقام أداء محددة.

## حدود النسخة الحالية

- يعتمد توليد مخططات PlantUML على خادم PlantUML خارجي، فيتطلب اتصالًا به وقت التحويل.
- المدخلات بصيغة Markdown والمخرجات بصيغة PDF فقط.
- لا توجد معالجة متوازية للمستندات الكبيرة، ولا ميزات تعاون أو إدارة إصدارات.
- لم تُنشر قياسات كمية للأداء؛ ما يذكره التقرير عن سرعة الاستجابة يستند إلى طبيعة البنية الطرفية لا إلى اختبار أحمال.

## تطويرات مستقبلية محتملة

بحسب الآفاق الواردة في المشروع، يمكن توسيع الخدمة عبر:

- دعم تنسيقات إدخال وإخراج إضافية، وقوالب احترافية قابلة للتخصيص.
- معالجة المستندات الكبيرة بصورة متوازية لتحسين الأداء.
- ميزات التعاون بين المستخدمين وإدارة الإصدارات.
- دمج الذكاء الاصطناعي لاقتراح تحسينات على بنية المستند واكتشاف الأخطاء قبل التحويل.
- دعم خدمات التخزين السحابي، وآليات أدق لإدارة الصلاحيات وتتبع الاستخدام.
- توسيع دعم MCP ليتكامل مع منصات ووكلاء ذكاء اصطناعي أكثر.

## هل تخطط لنظام مشابه؟

إذا كنت تعمل على أداة API أو تكامل MCP لتطويرك وتحتاج إلى مساعدة تقنية في تطوير الفكرة أو بناء نموذج أولي، يمكن التواصل مع **مكتب تكنو إنجاز** لمناقشة متطلبات المشروع ونطاق الدعم المناسب.
