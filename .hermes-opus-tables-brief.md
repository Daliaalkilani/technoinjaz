# Fix: article tables look cut off / broken on desktop (RTL)

## User report (with screenshot)
Article tables on DESKTOP look "مقطوعة" (cut off). Screenshot shows a small RTL comparison
table (المهمة / السؤال) where: the table's top edge/header is visually clipped mid-row,
column separation is unclear (rows blend into the dark background), and the wide empty area
on one side makes it look broken rather than a tidy table. On mobile the horizontal scroll
wrapper hides these issues; on desktop (wide, few columns) it looks broken.

## Files
- `src/styles/globals.css` (search `.md-table-wrap` ~line 1196) — the generic markdown table styles
- `src/features/articles/ArticleDetailView.css` (~lines 909+, 1597) — reader/fullscreen table styles
(keep both consistent)

## What "good" looks like (design bar — the owner hates clutter)
- Desktop: the table is a clean boxed card: visible outer border, rounded corners, header row
  clearly distinct (bg + accent color, e.g. #38bdf8 text), row separators subtle but visible,
  generous cell padding (12-18px), NO clipping of the header or outer border.
- RTL: `text-align: start`, th/td direction follows document; don't force LTR.
- Wide screens with few columns: distribute columns nicely (`width:100%`) instead of huddling
  content to one side with a large dead zone.
- Narrow screens: keep the existing horizontal-scroll behavior INSIDE the rounded box
  (don't break mobile).
- Find the actual clipping culprit: likely `border-collapse: collapse` + `border-radius` +
  `overflow-x: auto` on the same element (border-radius with collapsed borders doesn't clip
  properly; and overflow-x:auto makes overflow-y compute to auto → vertical clipping of header
  background). Fix the mechanism, not just cosmetics.

## Constraints
- Do not change table MARKUP or the markdown renderer's class names (`.md-table-wrap` is used
  elsewhere: projects, pages). Style-only changes.
- Test both themes (dark/light tokens exist).
- Run `npm run build` at the end (must pass). Do NOT deploy or commit — leave changes in tree.
